# Flarum 论坛发帖

> **本地适配说明（2026-10-21 装入本机）**
> 原稿写于另一套运行时，文中 `exec（本地 shell）` / `无（本机不适用）` 在本机不存在，对应替换为：
> `exec（本地 shell）` → `exec`；`browser 工具` → `browser` 工具（open/navigate/snapshot/act）；
> 其余流程、参数、坑位记录一律照原样保留。
> 凭据：`config.env` 需用户本人填写（论坛账号、COS 密钥），我不经手密码，也不写入日志或记忆。


## 何时用

- 用户要求在 Flarum 论坛发布主题帖时用本方法，适用于资讯搬运、公告通知、生活帖等常规发帖。

- 本方法不覆盖删帖、封禁、后台管理等操作，遇到这些需求另行处理。

## 前置条件

- 确认发帖必须登录账号，未登录时点"发起讨论"只会弹出登录框。

- 登录由用户在安全卡片上自行完成，你绝不经手密码和验证码。

- 发帖前向用户确认标题正文定稿、目标板块、发帖账号，三者缺一就先问齐再动手。

## 站点识别

- 用 `exec（本地 shell）` 以只读 GET 请求 `https://<论坛域名>/api/tags`，拿到全部板块的 name、slug、discussionCount，把每帖映射到对应板块。

- 公开讨论列表可直接 GET `https://<论坛域名>/api/discussions`，返回 JSON:API 格式（含 discussions、users、posts、tags），无需鉴权。

- 读取站点结构用只读 GET；发帖有两条路径：① 人工发帖走浏览器登录态；② **自动化发帖走 REST API（已验证，首选）**，见下文「API 发帖（自动化首选）」节。

## 发帖步骤

- 用 `browser 工具` 在已登录窗口点"发起讨论"，填标题、选 tag、填正文，检查无误后发布。

- 若编辑器没有标签选择器（本论坛实测如此），直接发，事后在管理后台按 slug 补标签；批量发帖时把建议标签记在 manifest 里一起交付。

- 一次只发一帖，每帖间隔几秒，避免触发限流。

- 遇到限流、报错或异常弹窗立即停止，不重试同一操作，如实汇报已成功和失败的帖子。

- 备选 API 路径：`POST https://<论坛域名>/api/token` 发送 identification 与 password 换取 token，后续请求头带 `Authorization: Token <token>`。Flarum 后台没有生成 API Key 的界面，API Key 只能手动写入数据库 api_keys 表。

## API 发帖（自动化首选）

- 鉴权：`POST https://<域名>/api/token`，JSON body `{"identification":"<用户名>","password":"<密码>"}`，返回 `token`。后续请求头 `Authorization: Token <token>`。token 会过期，自动化每次运行应先重新换取。
- 凭据来源：本机 `config.env` 的 `FORUM_USER` / `FORUM_PASS`（仅本地，严禁随包外发，不得写入日志/记忆/聊天记录）。
- 发帖：`POST https://<域名>/api/discussions`，JSON:API 载荷：
  `{"data":{"type":"discussions","attributes":{"title":"...","content":"..."},"relationships":{"tags":{"data":[{"type":"tags","id":"<板块id>"}]}}}}`
- 本论坛发帖编辑器**不渲染标签选择器**，标签必须通过 `relationships.tags` 显式指定板块 id；板块 id 从 `GET /api/tags` 获取。
- 一次一篇，篇间随机等待 10–30 秒；遇 429/报错立即停止，不连续重试。
- 成功返回 HTTP 201，响应含 `slug`，帖子链接为 `https://<域名>/d/<slug>`。

## 修改已有帖子的标签（实测坑，2026-10-19）

给已发布的帖子补/换板块，走 `PATCH /api/discussions/<id>`。**有三个必须同时满足的条件，缺一个就 500**：

1. Header 必须是 `Content-Type: application/vnd.api+json`（普通 `application/json` 会 500）。
2. `data` 里必须带 `id` 与 `type`。
3. **必须同时提交 `attributes.title`（与当前标题完全一致）**，只传 `relationships.tags` 单独会 500——这是该站最隐蔽的一个坑。保险做法：先 GET 拿现有 title，再原样回填。

```json
{"data":{"type":"discussions","id":"50",
  "attributes":{"title":"<当前标题原样>"},
  "relationships":{"tags":{"data":[{"type":"tags","id":"59"},{"type":"tags","id":"7"}]}}}}
```

- 该站允许一条讨论同时挂多个 primary 板块（如「鹤医声」+「并发症管理」），实测通过。
- **子板块会自动追加父板块**：若 tag 的 `parent` 指向「论坛大厅」(id=1)，帖子 PATCH 后会自动多出 `论坛大厅` 标签，即仍会出现在大厅列表。想让帖子完全脱离大厅，需在后台把该子板块的父板块设为「无」。
- PATCH 成功返回 200，但响应体常不含 `included.tags`，**必须再 GET 一次核验实际标签**，不能凭 200 判定。

## 表格 / HTML 的能力边界（实测，2026-10-19）

**结论：本站不能发原始 HTML，md 管道表格也不渲染，表格只能转图片。**

| 试法 | 结果 |
|---|---|
| 直接发 `<table>` / `<div>` / `<b>` 等 HTML | 被整体转义，页面上显示成源码文字（`<p>&lt;table&gt;...`） |
| 发 GFM 管道表格 `\| a \| b \|` | 不渲染，退化成一行纯文本 `\| a \| b \|<br>\|---\|---\|` |
| md 表格 → 图片 `![](url)` | ✅ 正常，移动端也一致 |

- 站点实况：**Flarum 2.0.0-rc.5**（PHP 8.3.35 / MariaDB 11.8.9 / Valkey 9.1.2 / Redis+Horizon 队列）。Flarum 的 s9e/TextFormatter 只开了基础 BBCode + Litedown，**刻意转义 HTML**（安全设计），没有开放 raw HTML 的开关。
- 因此脚本默认 `TABLE_MODE=image`：正文里的 md 表格会被 `md_table_image.py` 逐块渲染成紫系表格图（750px、2 倍图、表头 `#5c4a7a`、斑马纹），上传 COS 后替换成图片。批量和单篇脚本都已内置，无需手工处理。
- **若站长愿意装扩展**，装 `ekumanov/flarum-ext-markdown-tables`（Flarum 2.0 专用；1.x 的 askvortsov 版在此站不能用）。它只是打开 s9e 的 PipeTables，装完 md 表格直接原生渲染、可选中可复制、超宽时横向滚动：

  ```bash
  composer require ekumanov/flarum-ext-markdown-tables
  rm -rf storage/formatter/*    # 必须：清掉编译好的 Renderer，否则表格会渲染成空白
  php flarum cache:clear
  php flarum assets:publish
  ```

  然后在后台「扩展」里启用 Markdown Tables。装好后把 `config.env` 的 `TABLE_MODE` 改成 `md` 即可切回原生表格，不用重写稿件。注意：单列表格受 PipeTables 语法限制，仍不会渲染。
- 不建议为了表格去装「允许 HTML」类插件：本站是病友社区，放开 raw HTML 等于给所有注册用户开 XSS 面（历史上有过 CVE-2021-32671 这类事故），得不偿失。
- 已发布但表格坏掉的旧帖，用 `scripts/republish_tables.py` 批量修：`--scan` 先看哪些帖有表格，`--ids 137,138` 定点修，`--all` 全量修；脚本会自己 PATCH 回写并核验 `contentHtml` 里不再残留 `|--`。

```bash
python republish_tables.py --scan                 # 列出含 md 表格的帖子
python republish_tables.py --ids 137,138 --yes    # 定点修复
python republish_tables.py --all --yes            # 全量修复
python md_table_image.py body.md --out new.md --no-upload   # 单文件试跑，只看图不上传
```

## 内容规范（强制）

- 以真实身份发布（管理员或运营），绝不伪装成患者、家属、医生等虚假身份。

- 生活帖不虚构个人经历，不写无法证实的话。

- 资讯帖必须附来源链接，只转述公开信息，不做疗效承诺，不给用药建议。

- 按用户定稿一字不差发布，未定稿先起草给用户过目，确认后再发。

## 转发第三方内容（合规）

- 转发公众号文章、外部链接时，必须声明原作者/出处并附原文链接，标题注明【转载】或【分享】。
- 只提炼关键信息：用自己的话概括转述，不全文复制；直接引用原文不超过 50 字。
- 未经授权不做全文转载；作者明确禁止转载的不转。
- 医疗健康内容转发时同样遵守内容规范：不做疗效承诺，不给用药建议，加一句"具体请咨询主治医生"。

## 批量发帖（种子内容初始化）

- 适用：论坛冷启动，一次迁入几十篇公众号/历史文章。初始化阶段刷屏可接受，但仍建议随机间隔 30–60 秒，既防限流又能真实压测系统承载。
- 来源整理（先做这步）：
  - 去重：文件名带 `(2)`/`(1)`/`.bak`/“手动优化版”的是版本迭代，只留最新一篇；同一主题已发过的跳过。
  - 剔除内部文档：策划书、委员会提案、合作方案、监测日报、样张模板不发到患者论坛。
  - 一个 md 里含多篇（如“文章1/2/3”）要拆成多帖。
- 内容转换：公众号 HTML 先转干净文本再发帖——去掉 `<script>/<style>`，`<h1-6>/<p>/<br>/<li>` 转成对应 markdown，全角空格与多余空行压掉。标题从正文大标题提取，人工校一遍；标题缺失时用文件名兜底。
- 每帖统一加头尾：头加一句出处（如“本文转自小胰宝助手公众号原创内容”），尾加“⚠️ 本文仅供科普参考，不构成医疗建议。具体诊疗请咨询主治医生。”和落款。
- 建 manifest：每帖记文件名、标题、建议标签 slug、字数，便于核对进度和事后补标签。
- 发帖执行：把帖子文本存成单个 txt（`TITLE:`/`SUGGEST_TAG:`/`====`分隔头+正文），每批 5–10 个文件授权给浏览器任务，指令写明“逐帖发布，每帖之间随机等待 30–60 秒；遇到 429/限流/报错立即停止并汇报已发清单”。
- 有原文 md/html 时优先用原文，不要烧 token 让浏览器去读微信（微信“环境异常”滑块验证浏览器能过，但费时）。

## 批量投递脚本（`scripts/batch_publish.py`）

把「要点截图 → 裁剪白边 → COS 图床 → 发帖 → 核验 → 写日志」整条机械流程固化，避免每篇手工重复。
**内容提炼仍需人/LLM 预先写进稿件**，脚本只负责可靠执行。

稿件目录里一篇一个 `*.json`（按文件名排序执行）：

```json
{
  "title": "【转载】xxx",
  "tag_id": "30",
  "tag_ids": ["59","30"],
  "source_file": "/abs/path/原文.md",
  "shot_html": "/tmp/xxx.html",
  "body": "/tmp/xxx_body.md",
  "source_url": "http://...",
  "author_note": "某公众号（作者）微信原文",
  "image_key": "xyb/hys/20250918-tumor-marker.png"
}
```

`title/tag_id/source_file/shot_html/body` 必填；`image_key` 省略时按源文件名自动生成。
`tag_ids`（数组）优先于 `tag_id`，用于同时挂多个板块（如子板块「鹤医声」+ 原主题板块）。

```bash
# 看队列 + 判重结果（不做事）
python scripts/batch_publish.py --queue <稿件目录> --list
# 空跑：只渲染截图并上传，不发帖（用来核对版面）
python scripts/batch_publish.py --queue <稿件目录> --dry-run
# 正式发，本次最多 3 篇
python scripts/batch_publish.py --queue <稿件目录> --limit 3 --interval 20
```

- **判重**：读发帖日志里的 `- 源文件:` 行按**文件名**比对，已发的自动跳过；`--force` 可强制重发（慎用）。
- **截图**：Chrome headless 必须带 `--no-sandbox`；渲染 750 CSS 宽 @2x，Pillow 裁掉底部白边；若内容触底（疑似截断）自动加高重试（3000→6000→12000）。
- **正文配图**：`body` 首行若是图片会被替换成本次上传的图床链接，否则自动前置一行 `![](url)`。
- **核验**：发完回查板块、首帖字数、是否含图，不合格会标「需复查」。
- **日志**：自动追加到项目根的 `flarum-post-log.md`（序号自动递增，源文件存相对路径）。
- **失败处理**：单篇异常不中断整批，最后汇总「成功/跳过/失败」；有失败时退出码为 1。

## 图片处理

- Flarum 靠 FoF Upload 扩展上传图片，正常时编辑器有上传按钮。

- 若编辑器未渲染上传按钮（无工具栏、无 file-input 控件），停下先排查管理后台扩展设置和用户组上传权限，不要跳过图片强行发帖。

- 备选方案是图床外链加 markdown 图片语法嵌入正文，注意外链有效期，48 小时过期的临时链接不适合长期帖。

- 长期图床方案（已验证，腾讯云 COS）：用 `scripts/upload_image.py <本地图片路径>` 上传，脚本读取 `config.env` 中的 COS_SECRET_ID、COS_SECRET_KEY、COS_BUCKET、COS_REGION，上传为公开读并返回永久 URL，正文用 `![](URL)` 嵌入。`config.env` 只放你自己的密钥，不要外传；随包只带 `config.env.example` 模板。

- 文章截图路线（已验证）：本地 headless chromium 在本环境因代理问题截不出图。改走浏览器“打印存 PDF”→ 本地 `pymupdf` 按页转 PNG（`page.get_pixmap(dpi=100)`）→ 传图床。长文章只取前 1–2 页做截图示意即可。

## 发帖前的自检清单（2026-10-23 定）

事实密度高的帖子（药物管线、临床阶段、登记号、剂量阈值、政策流程）按这个顺序走：

1. **先查原始来源，再落笔**：ClinicalTrials.gov 用 `/api/v2/studies/<NCT>` 取 `overallStatus` / `enrollmentInfo` / `eligibilityCriteria`；医学阈值回到 AGA/ESMO/ASPEN 等指南原文。公司新闻稿只能作「公司口径」标注，不能当独立事实。
2. **区分三种数值**：登记口径（estimated/actual）、公司公告（首例给药、完成入组）、作者预测。三者混写是这类帖子最常见的事故源。
3. **入组条件要写死**：只招 KRAS G12D 的试验必须写明「野生型不符合」，不要让读者以为自己在范围内。
4. **重要内容过一遍 codex 复核**（见 `~/clawd/TOOLS.md`「Codex 二道复核」）。⚠️ codex 会错：它给的意见必须逐条回登记库/原文核验再采信（实例：它把 PT0253 入组数说成 240，登记实为 300）。

## 已发帖的纠错：原地 PATCH，不要删帖重发

发现错误时优先修正原帖，链接与讨论都保留，对读者更友好：

```bash
# 取正文
GET  /api/posts/<id>            # attributes.content
# 改正文（整体替换 content，先做字符串替换再提交）
PATCH /api/posts/<id>           # {"data":{"type":"posts","id":"<id>","attributes":{"content":"..."}}}
# 改标题
PATCH /api/discussions/<id>     # {"data":{"type":"discussions","id":"<id>","attributes":{"title":"..."}}}
# 增补一条回复
POST /api/posts                 # relationships.discussion → {"data":{"type":"discussions","id":"<id>"}}
```

要点：

- `PATCH` 必须带 `Content-Type: application/vnd.api+json`，否则 415/400。
- 改标题后 Flarum 会重算 slug；若已把旧链接发出去，提醒用户确认旧链是否仍可访问。
- 段落太多、主题偏离时，**拆成独立回复**比继续堆在主帖里好（实例：212 的「江苏路径」拆为 post 408）。
- 删帖（`DELETE /api/discussions/<id>` → 204）只在整帖方向错误时用；它会连读者提问一起消失，慎用。
- 改完必须重新 GET 回来抽查关键词，确认替换真的生效（`未匹配` 列表为空）。

## 对外稿件纯净度：只发成稿（2026-10-28 用户强约束）

**这是硬规则，优先级高于「写得自然」「有现场感」。**

发到论坛/公众号的，只能是**成稿内容**。以下东西一律不许出现在正文里：

1. **内部对话原文**：群聊片段、私聊记录、逐字引用他人发言
2. **内部讨论过程**：谁提出的、讨论了几轮、怎么改的、为什么这么定
3. **话题来源的指认**：「今天群里有人问」「刚才某某说」「我们昨天聊到」——要写就写成「有家属问过」这类泛化表述
4. **他人经历的冒用**：把群友的真实经历写成第一人称「我家」「我当时」。第一人称只能用于**作者本人真实经历**
5. **内部规划草稿**：尚未公开的城市名单、合作意向、未定稿的策略
6. **可识别信息**：志愿者昵称、群名、医院内部人员姓名、截图里的头像与 ID

**改写原则**：从「事件」提取「方法」，从「讨论」提取「结论」。读者需要的是能用的东西，不是这场讨论怎么发生的。

**发布前必查（grep 一遍，命中就改）**

```bash
grep -nE "今天群里|昨天|刚才|有人问我|我们讨论|我说|某某说|内部|草稿|暂定" 稿件.md
```

再查人名与昵称：

```bash
grep -nE "志愿者姓名|群昵称" 稿件.md
```

**自检三问**

1. 这段话，如果被群里的当事人看到，会不会觉得「我的事被写进去了」？
2. 这段描述，作者本人真的经历过吗？
3. 去掉「谁说的、怎么讨论的」之后，内容还成立吗？——如果不成立，说明写的是过程而不是成果，重写。

**违规案例（2026-10-28，两次）**

## 群聊素材预处理（用户粘贴聊天记录时的标准动作）

用户常把群聊整段粘过来。**不许直接抄、不许直接发**，先做四步预处理。

### 第一步：抽出「问题」

用一句话概括这堆对话在争什么，例如：

> 原始材料：七八个人在聊两位医生意见不同怎么办
> 抽出问题：**当两位医生给出的方案不一致时，家属该按什么标准定夺？**

判断标准：抽出的问题必须**脱离聊天语境仍然成立**，别人看到这句话能直接回答。

### 第二步：拆「观点」（不是拆「谁说了什么」）

| 代号 | 核心主张 | 依据类型 | 可采信度 |
|---|---|---|---|
| A | 再找第三方专家听意见 | 经验 | 中 |
| B | 没有套路，只能具体分析 | 经验 | 中 |
| C | 本质是选主治：看临床量、后线思路、沟通 | 经验+共识 | 高 |

要点：
- **只记主张，不记语气、不记原话**
- 「依据类型」分三类：指南/文献、经验、个人偏好——这决定它在成稿里能被写成什么强度
- 「可采信度」是给自己看的，不进正文

### 第三步：给代号，不给名字

- 默认用 **A / B / C / D**
- 需要「有人说话」的语气时，用**中性卡通昵称**：`山雀`、`竹节`、`小满`、`阿禾`、`老树`、`灯芯`
- 禁止：真实姓名、微信昵称、职业+姓氏（如「张医生」「李主任」）、地名+身份（如「太原那位」）
- 代号一经分配，**全篇一致**，不要中途换

### 第四步：写成稿（只留结果）

成稿里应该只有：**问题 → 观点（去标识）→ 判断/方法 → 边界**。
不该有：谁先说的、谁反驳了谁、讨论了几轮、谁最后被说服。

对照检查：
- 把代号全部删掉，文章还成立吗？→ 成立，说明写的是结论
- 不成立，说明你写的是过程，回去重写

### 抽观点的三个提问

拿到一段聊天，问自己：
1. 这里面**有哪几种互不相同的立场**？（通常 2–4 种，不是每人一种）
2. 哪种立场背后有**指南或数据**？（这类可以写强）
3. 哪种只是**个人经验或偏好**？（这类必须写成「有人觉得」，不能写成结论）

### 反例（2026-10-28）

原始材料里有人点名两位医生、有人问「是中肿的吗」、有人纠正「是张晓飞不是张晓东」。
这些**全部不进正文**：姓名、口误、澄清过程，都是内部信息。
成稿只保留：分歧可以有三种性质、问医生的六个问题、求交集先动起来。
